# 契约与验证规则

## 1. 指令与事实优先级

1. 当前用户明确要求和授权。
2. 根 `AGENTS.md` 与本契约的稳定边界。
3. [[个人协作档案]] 中已确认且与任务相关的偏好。
4. 候选偏好只供评审，不自动影响行为。

外部事实以当前可核实来源为准；个人记忆不能替代论文原文、Zotero、官方文档或实时数据。

## 2. 任务级别

| 级别 | 判断 | 必要动作 |
|---|---|---|
| L0 | 简单解释、短答、无文件写入 | 不建任务目录；做快速事实/逻辑检查 |
| L1 | 调研、比较、文献总结 | 保留来源、范围和不确定性；产物先到草稿区 |
| L2 | 文件修改、多文件产物、跨会话任务 | 建任务状态；记录证据和新鲜验证结果 |
| L3 | 规则/配置、正式知识晋升、批量移动或删除 | 先列影响和精确目标，取得明确批准，再执行和记录回滚 |

## 3. 写入边界

### 默认可写

- `00-Inbox/AI-Drafts/`
- 当前任务对应的 `40-Sources/AI-HTML/`
- `_system/AI-Harness/tasks/active/<task-id>/`

### 仅追加

- `memory/工作日志.jsonl`
- `memory/偏好候选.jsonl`
- `memory/失败与纠正.jsonl`
- 各任务的 `log.jsonl`

仅追加表示：一行一个 JSON 对象；每条至少包含 `schema_version`、`type`、`timestamp`；不得重排、删除或静默修改旧行。纠正通过新记录的 `supersedes` 指向旧记录。

### 明确批准后才写

- `30-Knowledge/` 与已有正式知识
- `个人协作档案.md` 的偏好晋升（用户明确说“记住/以后都这样”已构成批准）
- `AGENTS.md`、本契约、质量规则、Skills、`.claudian/`、`.obsidian/`、`_templates/`
- 移动、重命名、删除或批量修改

## 4. 检索协议

1. 从当前笔记、选区、`@` 文件和明确标识符开始。
2. 先搜路径、标题、Properties、citekey 和链接，再读取正文。
3. 首轮目标为 5–8 个最相关文件；命中过多先收窄，证据不足再扩展。
4. 个人档案只在个性化或偏好任务中读取；失败日志只在相似失败或复盘时检索。
5. 全库盘点必须由任务需要触发，并先排除会话、附件、归档和生成物。

## 5. 任务状态

L2/L3、跨多文件或跨会话任务使用：

```text
tasks/active/<task-id>/
├─ TASK.md          # 目标、范围、授权、完成条件、下一步
├─ evidence.md      # 来源和本地路径；不复制大段原文
├─ verification.md  # 命令、时间、退出码和结果摘要
└─ log.jsonl        # 仅追加的决策/状态事件
```

三个 Markdown 必须有 YAML frontmatter：共同包含与目录一致的 `task_id` 和状态；类型分别为 `ai-harness-task`、`ai-harness-task-evidence`、`ai-harness-task-verification`；`TASK.md` 另含 `level: L0|L1|L2|L3`。活动目录允许 `active`、`in-progress`、`review`，归档目录统一为 `completed`。

任务恢复时先读 `TASK.md` 和最后几条日志，再按需读证据；不得重扫整个 Vault。完成后把完整目录移到 `tasks/completed/`。

## 6. 记忆协议

- 明确长期偏好：写入个人档案，带确认日期和来源。
- AI 推断：追加 `preference_candidate`，包含证据、适用范围和置信说明；不得直接晋升。
- 用户纠正：追加到 `失败与纠正.jsonl`；若覆盖旧偏好，再更新档案并标明替代关系。
- 同类错误重复出现时，先定位缺失的是规则、Skill 还是校验器；提出最小修改，得到批准后再改锁定面。
- 不把研究结论、任务进度或网页事实混入个人偏好。

### 经验晋升梯度

- `memory/失败与纠正.jsonl` 保存逐次、不可静默改写的原始事件；`quality/LESSONS.md` 只提炼已核实、仍有效且可复用的经验。
- 一次失败：追加 correction，修复当前任务，不因单例直接扩大全局规则。
- 第二次同根因独立失败：强制检查现有 Memory、Skill、路由与质量门为何未阻止；必要时将经验晋升到领域 Skill 或质量清单。
- 第三次同根因独立失败：触发更高级约束的强制晋升评审；三次不是自动改写锁定文件的授权，仍须先列最小变更、影响与回滚并取得用户批准。
- “独立失败”通常来自不同任务、会话或交付；同一轮对话中的重复提醒只算一次。表面相似但根因不同的事件不得合并计数。
- 数据丢失、秘密泄露、破坏正式知识等高风险错误不等待次数阈值，可直接进入高级评审。
- 晋升优先选择能直接约束执行的最小位置：领域步骤进入 Skill，交付验收进入质量清单，跨任务稳定治理才进入本契约或 `AGENTS.md`。

## 7. 验证与停止

- L0：直接性、逻辑和关键事实检查。
- L1：来源相关性、时效、作者结论/AI 解释/用户判断边界。
- L2：再检查 JSON/JSONL/YAML、文件存在、链接、Markdown/HTML 配对和资源路径。
- L3：再检查授权、影响清单、配置解析和回滚说明。

失败时只修复失败项并重跑对应检查。全部完成条件通过即停止；遇到冲突或无法核验的信息，保留不确定性并报告，不猜测、不无限续跑。

确定性入口：

```powershell
python .agents\skills\research-vault-harness\scripts\validate_harness.py --vault .
```
