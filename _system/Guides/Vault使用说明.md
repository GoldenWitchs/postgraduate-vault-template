# Vault 使用说明

## 一条内容放哪里

| 判断 | 位置 |
| --- | --- |
| 尚未处理或尚未核验 | `00-Inbox` |
| 有明确交付物和结束点 | `10-Projects` |
| 需要长期维持 | `20-Areas` |
| 已核验且可跨项目复用 | `30-Knowledge` |
| 原始材料、网页或 HTML 附件 | `40-Sources` |
| 已完成或失活 | `90-Archive` |

## 最小工作法

1. 捕获时只要求来源和一句话说明，不在收集阶段过度分类。
2. 阅读时先明确问题，再让 AI 解释；不做无目的全文总结。
3. AI 产物保留 `ai-draft`，对照原文后再改为 `verified`。
4. 同一个概念在至少两个项目中复用，或对当前研究特别关键时，再建立独立概念卡。
5. 项目通过链接使用知识，不复制文献笔记。

## 每周复盘

- 清理收件箱，解释所有仍需保留的未处理项。
- 每个活跃项目必须有一个清晰的下一步行动。
- 检查本周 AI 草稿的证据位置和核验状态。
- 更新研究主题 MOC，而不是追求关系图“看起来很密”。
- 归档已经完成、暂停或取消的项目。

## 备份与同步

- 同步解决多设备一致性，不能替代可恢复备份。
- 文本内容适合使用私有 Git；大量 HTML、图片和 PDF 应避免无限进入 Git 历史。
- 修改目录结构、插件或批量移动前，先建立快照。
